# 01 — Vision and category

**Status:** living  
**Owner:** founder  
**Decides:** Category claim, what we are not, 3-year shape.

## Problem

Spire AI needs a sharp public category so investors, hires, and early users do not file it under “another Copilot wrapper” or “Jira with XP points.”

## Recommendation

### One-paragraph vision

Spire AI builds **video games for building software with AI**: you play a climb where the enemies are real SDLC work, the deck is your agent’s skills and rules, and the save file lives in your repo. One room at a time. Entertainment is the wedge that makes single-task discipline stick; AI weights the foggy map nodes, the player chooses the path.

### Category sentence

**Video games for building software with AI** — not a project tracker, not an autopilot PM, not a skin on a coding agent.

### Anti-positioning (we are not)

Pull and keep aligned with [non-goals](../non-goals.md):

| We are not | Why it matters |
| :-- | :-- |
| Jira / Linear with gamification | Backlog ownership is out of scope; we structure *how you work one task*, not *what’s on the board* |
| Copilot / Cursor skin | Those are the runtime; we are the run structure + deck + rooms |
| Autopilot PM | AI proposes priors on `?` nodes; the player always chooses |
| Points / badges / streaks-as-product | Habit metrics serve the loop; they are not the product |
| Silent repo mutator | Deal and acceptance paths are explicit and user-confirmed |

### 3-year shape

| Layer | Role |
| :-- | :-- |
| **Engine** (this repo / plugin) | Deal deck, rooms, packs, ascension; open enough to dogfood |
| **Client** (MCP app in Cursor) | One-room UI facets: map, combat, reward, campfire, shop |
| **Packs + climbs** | Authored content — verticals and disciplines as the content engine |

Near-term proof is Stage 2: Ship-the-stub demo ([wedge](../wedge.md)). Long-term category ownership is the loop + content, not a single IDE feature.
