# 07 — Moat and content strategy

**Status:** living  
**Owner:** founder  
**Decides:** Moat order; first packs and climbs to fund after the demo.

## Problem

Tech alone (detector, MCP chrome) is copyable. We need an ordered moat thesis and a concrete content backlog so Stage 4–6 funding isn’t random.

## Recommendation

### Moat order (do not reverse)

1. **Loop fun + single-task habit** — if clear/skip isn’t sticky, nothing else matters.
2. **Authored packs / climbs as content engine** — verticals and disciplines compound faster than engine features.
3. **Save-file reality bridge** — `.spire/` in real repos creates switching cost and social proof.
4. **Brand / category** — “video games for building software with AI” after the loop is proven.

### Content roadmap tie-in

| Wedge stage | Content focus |
| :-- | :-- |
| Stage 2 | Ship-the-stub climb only — prove loop |
| Stage 4–5 | First packs + additional climbs |
| Stage 6 | Vertical expansion; still no marketplace payments until exec revisit ([04](04-business-model.md)) |

Schemas: [content-schema.md](../content-schema.md). Pack tooling already exists in-engine (`packs/`, `/spire:shop`).

### First 3 packs to fund (after demo)

| Pack | Job |
| :-- | :-- |
| **Testing discipline** | Already started in-engine — harden as the flagship pack |
| **API / endpoint craft** | Pair with “add endpoint” style rooms; Defect-leaning |
| **Review & merge hygiene** | PR/review rooms; relics that keep review rules lean |

### First 3 climbs to fund (after demo)

| Climb | Job |
| :-- | :-- |
| **Ship-the-stub** | Stage 2 flagship; keep as onboarding climb forever |
| **Add-an-endpoint** | Second vertical; maps to common ICP week |
| **Green-the-suite** | Test-failure boss floor; pairs with testing pack |

Do not fund marketplace UX before these six content bets have at least one external clear each.
